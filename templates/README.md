# Templates

Ten ready-made n8n workflows — the [build spec](https://docs.n8n.io/integrations/community-nodes/build-community-nodes/)'s original six, plus four adapted from the worked examples in the main [README](../README.md) — exported as workflow JSON. Each file is a complete n8n workflow: nodes, their settings, and sticky notes that explain the workflow. Import one with **n8n's `...` menu > Import > From File** (or, on n8n versions before 3.0, **Import > From URL** if you host the raw file — that option is removed in 3.0), add your own credentials, and run it.

This folder is the source of truth for these templates — the place to review and version them, test them against new MCP server releases, and link to directly from docs or the landing page. It's also the staging area before submitting to the [n8n template gallery](https://n8n.io/workflows/), which reviews every submission against its [template guidelines](https://docs.n8n.io/integrations/creating-nodes/build/reference/) and, more specifically, its [template submission guidelines](https://n8n.notion.site/Template-submission-guidelines-9959894476734da3b402c90b124b1f77) — checked in full against every template here; see "Before submitting to the gallery" below for what that turned up.

`@unleash/n8n-nodes-unleash` is now [verified by n8n](../README.md) and live on n8n Cloud (since 2026-11-23) — relevant below wherever a template's sticky note talks about install surface.

## Uses the community node

Five templates depend on `@unleash/n8n-nodes-unleash` (tested at **v0.1.2**): **Agent kill switch**, **Guarded automation**, **Flag-gated deploy gate**, **Route a tenant by variant** and **Gate an AI agent's tools by flag**. Per the template submission guidelines' "Templates with community nodes" section, each one's sticky note now names the package, states the tested version, links to n8n's community-node install docs, and says it's available on both n8n Cloud and self-hosted — true as of the node's verification on 2026-11-23. The other five use only n8n's own built-in nodes (Webhook, If, Switch, Remove Duplicates, Slack, Jira, Schedule Trigger, AI Agent, MCP Client) — the Enterprise ones among them still need a real Unleash Enterprise instance to test against before they're submission-ready, independent of the node's own verification status.

## Caching and usage reporting

The five templates that use the community node ([Caching](../README.md#caching) in the main README has the full reasoning): both of the node's operations cache their result for 30 seconds by default, and Evaluate's Report Usage is off by default. [`agent-kill-switch.json`](agent-kill-switch.json) sets **Cache Duration (Seconds)** to `3` — the one template here actually named a kill switch and built on the Unleash node, where the 30-second default would mean up to 30 seconds before the workflow notices a flag flip. It deliberately isn't `0`: a kill switch still follows the same consistency model as every other flag, just with a shorter window. The other four (including [`guarded-automation.json`](guarded-automation.json), which also carries a kill-switch flag but runs on a schedule, not per-request) keep the 30-second default, since none of them needs a faster reaction and the whole point of the default is fewer calls to Unleash.

Once a cache entry goes stale, every one of these gets a second, independent saving on top, on either a standard Unleash server or Edge: the node revalidates with `If-None-Match` before refetching, and a `304` replaces resending the full body when nothing changed. That applies even to `agent-kill-switch.json`'s 3-second window — every execution past that window still checks live, it just isn't billed the full response again when the flag hasn't moved.

## Enterprise requirement

The four Enterprise templates all call the Unleash MCP server, which Unleash Enterprise hosts at `https://<instance>/api/admin/mcp` — see the [MCP integration docs](https://docs.getunleash.io/integrate/mcp). Each one's sticky note links to [Unleash's Enterprise trial](https://www.getunleash.io/plans/enterprise-payg) and carries "(Enterprise)" in its title, matching the n8n gallery convention for plan-gated templates.

## n8n 3.0 compatibility

n8n 3.0 ships its own [breaking-changes list](https://docs.n8n.io/changelog/v30-breaking-changes) (beta out now, [stable expected early December 2026](https://blog.n8n.io/introducing-n8n-v3)). We checked all ten templates and the node itself against every rule in it:

- **Nothing here uses a removed or changed node type, version, or expression helper.** No legacy Function/Cron/old-AI nodes, no `$getPairedItem` or `$evaluateExpression()`, no `alwaysOutputData` on a multi-output node. Every AI Agent node here is already on v3.1 (v2 is the floor n8n 3.0 keeps), and the Execute Workflow node in `route-tenant-by-variant.json` already sources from Database, not the Local File/URL modes that are removed.
- **Slack API credentials need a Signature Secret to be saved on n8n 3.0+, and a Slack Trigger can't be activated without one.** The five templates that use a Slack credential (`incident-kill-switch.json`, `weekly-cleanup-sweep.json`, `change-request-approvals.json`, `route-tenant-by-variant.json`, `ops-agent-in-slack.json`) now say so in their sticky notes — `ops-agent-in-slack.json`'s Slack Trigger is the one this actually blocks from activating, not just the credential save.
- **"Import > From URL" is removed from the editor in n8n 3.0** — the instructions at the top of this file now call it out as a pre-3.0 option; "Import > From File" keeps working on every version.
- **The node package itself needs no code changes.** It has no runtime dependencies — `unleash-proxy-client` is a type-only import, compiled out of `dist/` entirely — so it already meets the no-runtime-dependency requirement for n8n's separate Verified Community Node Program.
- **Not addressed here on purpose:** n8n 3.0 also flips `N8N_UNVERIFIED_PACKAGES_ENABLED` to `false` by default, so an unverified community package — which `@unleash/n8n-nodes-unleash` still is — stops loading unless an instance sets that variable explicitly. We're deferring documenting that until promotion starts, on the assumption the node will be verified by then. If verification is still pending when n8n 3.0 ships, this is the variable to document.

Everything else in n8n 3.0's breaking-changes list — Docker-only deployment, task runner and storage defaults, external secrets role defaults, the chat hub, and so on — is an instance-level or deployment concern, not something a workflow template or this node is affected by.

- [x] Each template names a practical use case (above).
- [x] Each template was tested by importing the exact JSON here into a fresh workflow.
- [x] No leaked secrets or private identifiers — checked directly, not assumed: `pinData` is empty `{}` in all ten files (a standard export field, not real pinned data), no embedded email addresses, every credential reference already uses `"id": "placeholder"` with a generic name (e.g. "Unleash Frontend account"), and every externally-facing URL is a clear placeholder (`your-unleash-instance`, `your-deploy-api.example.com`).
- [x] An image for all five community-node templates, each (re)captured at retina resolution (2800x1740) from a real `npm run dev` instance, with the n8n 3.0 banner and onboarding dialogs hidden first: `docs/images/guarded-automation.png`, `flag-gated-deploy-gate.png`, `route-tenant-by-variant.png`, `gate-ai-agent-tools-by-flag.png`, and the new `agent-kill-switch.png`. Recapturing also caught a real bug: the sticky notes' new paragraph (tested version + install link) didn't fit in the box heights set when that text was added, so the note text spilled past the box into the node row below — fixed by resizing and repositioning all five sticky notes to fit the actual rendered content exactly.
- [x] Every community-node template's sticky note names `@unleash/n8n-nodes-unleash`, states the tested version (0.1.2), links to n8n's [community-node install docs](https://docs.n8n.io/integrations/community-nodes/installation-and-management/gui-installation), and says it's available on both n8n Cloud and self-hosted — per the guidelines' "Templates with community nodes" section.
- [ ] **Not yet done, and a real gap per the guidelines, not just a risk we flagged ourselves:** "test the exact JSON file you plan to submit... run the complete workflow with representative input, check the final result in the destination service" — the four Enterprise templates are still "Structural only," never run against a live Unleash Enterprise instance. They aren't submission-ready as written; this needs real Enterprise access to close, not more repo work.

## A note on scope

Submission itself — creating an n8n Creator Portal account and uploading these — is a decision for a person, not something this repo automates: whether the account belongs to Unleash or an individual shows up on every published template's creator profile, and new creators can only submit one template at a time until they reach three approvals. That decision, and the one-at-a-time submission order, are tracked outside this folder.
